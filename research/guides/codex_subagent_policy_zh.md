# Codex Subagent 启用策略与模型分配规范

## 1. 目的与适用范围

- 本规范用于约束 Codex 在本仓库中的 `subagent` 启用策略、模型强度分配和协作边界。
- 目标是在不牺牲正确性的前提下，用“平衡启用”策略降低主路径等待时间，并把可并行的探索、实现或验证任务拆分给合适强度的模型。
- 本规范不修改 `C:\Users\荀冢小宝宝\.codex\config.toml`；实际执行仍服从更高优先级的系统、运行时和会话级规则。

## 2. 默认策略：平衡启用

- 只有当并行 delegation 能明显减少等待、降低风险，或让旁路任务独立推进时，才启用 `subagent`。
- 主 agent 默认先承担当前关键路径；`subagent` 主要用于并行代码搜索、局部实现、独立验证和其他不阻塞主线的子任务。
- 简单任务默认本地完成；中等任务在边界明确且可并行时启用一个 `subagent`；复杂或高风险任务按模块或验证流拆分多个 `subagent`。

## 3. 复杂度分级与模型映射

| 复杂度 | 典型任务 | 启用策略 | 推荐模型 | 推荐 reasoning effort |
| --- | --- | --- | --- | --- |
| 简单 | 简短问答、单文件小改动、一次性检查 | 不启用 `subagent`，主 agent 直接完成 | - | `low` / `medium` |
| 中等 | 有明确边界的代码搜索、局部实现、局部验证、有限文档整理 | 仅在可并行且不阻塞当前主线时启用 `1` 个 `subagent` | 探索用 `gpt-5.1-codex-mini`；实现/验证用 `gpt-5.3-codex` 或 `gpt-5.2-codex` | `medium` |
| 复杂 / 高风险 | 跨模块设计、歧义较大的调试、高风险重构、关键正确性验证 | 主 agent 保持主线，按独立模块或验证流启用多个 `subagent` | 关键流优先 `gpt-5.4`；受限子任务可用 `gpt-5.3-codex` / `gpt-5.2-codex`；轻量搜索仍可用 `gpt-5.1-codex-mini` | `high` / `xhigh`（关键流），`medium`（受限子任务） |

### 模型选择细则

- `gpt-5.1-codex-mini`：轻量探索、代码搜索、只读分析、很小且隔离的改动。
- `gpt-5.3-codex` / `gpt-5.2-codex`：常规实现、普通调试、局部测试修复、边界清晰的文档或脚本工作。
- `gpt-5.4`：跨模块设计、歧义较大的问题定位、高风险改动、关键验收或独立审查。

## 4. 何时启用，何时不启用

### 适合启用 `subagent`

- 主 agent 可以继续推进主线，同时把旁路搜索、局部验证或独立实现并行出去。
- 子任务边界清楚，输入、输出和完成标准可以一次性说清楚。
- 任务可以按目录、模块或文件拆开，多个代理之间不会争抢同一写入范围。
- 需要一个独立视角做事实收集、关键验证或风险复核。

### 不适合启用 `subagent`

- 当前下一步就是主线关键阻塞，主 agent 立刻需要该结果才能继续。
- 任务过小，delegation 的沟通和等待成本高于本地执行成本。
- 子任务边界模糊，强依赖当前上下文，或需要频繁来回澄清。
- 多个子任务很可能改到同一文件、同一接口或同一逻辑块，容易引入冲突。

## 5. 并行拆分与协作边界

- 每个 `subagent` 都必须有明确职责、预期输出和文件或模块 ownership。
- 多个 `subagent` 并行写入时，优先保证写入范围互不重叠；如无法避免，改由主 agent 保留该部分实现。
- 读多写少的事实收集优先交给 explorer 风格的 `subagent`；带有明确交付物的局部实现或验证优先交给 worker 风格的 `subagent`。
- 主 agent 在 `subagent` 运行期间继续处理非重叠工作，不因“等结果”而空转；只有在下一步确实被阻塞时才等待。
- 主 agent 负责统一集成、冲突处理、接口对齐、最终验证和面向用户的交付说明。

## 6. 典型示例

- “解释一个脚本做什么”或“改一个 Markdown 标题”：不开 `subagent`。
- “主 agent 正在修一个局部 bug，同时需要确认调用链或配置入口”：可并行启用 `1` 个轻量探索 `subagent`。
- “跨多个模块排查问题，并补独立验证”：主 agent 走主线，按模块搜索、局部实现、验证拆给多个 `subagent`，并按风险选择 `gpt-5.4` 或常规模型。

## 7. 落地检查

- 启用前确认：该子任务是否能独立完成、是否能并行推进、是否真的节省总时间。
- 完成后确认：ownership 是否清晰、接口是否兼容、是否需要补文档或 smoke check 说明。
- 若实际任务与本规范冲突，以更高优先级的系统或运行时规则为准，并由主 agent 在最终交付时显式说明采用了哪条覆盖规则。
